# תרגיל פרק 36: `question-bank`, ראיונות תכנון מדומים ומאגר השאלות

**מטרה:** שני ראיונות תכנון מדומים, בקול ועם שעון, עם ציון עצמי ותיקונים כתובים; ואחר כך מבחן עצמי על מאגר של
135 שאלות על כל הספר, עם `quiz`, כלי קטן שמגריל שאלות, מראה את התשובה ב־Enter, ומסכם מה לא ידעת. בתרגיל הזה לא
בונים קוד: הכלי מוכן ובדוק, והעבודה היא התרגול.

**זמן משוער:** שני ימי לימוד. יום 96: כ־65 דקות (ראיון מדומה 45, ציון והשוואה 15, מעבר מהיר על שני מקרים 5).
יום 97: כ־85 דקות (ראיון מדומה 45, ציון 10, הכלי, המבחן העצמי ורשימת הנושאים החלשים 30).

**ידע מקדים:** פרק 36 (השעון, הלוח וששת המקרים); פרק 29 (שיטת ששת הצעדים, והמחשבון שבו תשתמשי להערכות); פרק 7
(פרויקט uv: בדיקות, בדיקת סגנון ובדיקת טיפוסים). התרגיל לא מייבא קוד מתרגילים קודמים. הכלי משתמש רק בספרייה הסטנדרטית של Python,
והגרסאות של כלי הפיתוח מקובעות ב־`pyproject.toml` (נכון לאוקטובר 2026, ראי נספח ג).

## יום 96: ראיון מדומה על מערכת ההתראות

**1. העתקה.**

<div dir="ltr" align="left">

```bash
mkdir -p ~/senior-course/ch36
cp -r $COURSE/exercises/ch36-question-bank/solution/. ~/senior-course/ch36/quiz/

cd ~/senior-course/ch36
cp templates/mock-scorecard.md mock-1-notifications.md
```

</div>

**2. קריאה, בלי סעיף 36.4.** קראי את סעיפים 36.1 עד 36.3. את סעיף 36.4, מערכת ההתראות, לא קוראים עדיין: זה
המקרה של הראיון.

**3. הראיון.** דף ריק או לוח, טיימר של 45 דקות, והשאלה: „תכנני מערכת התראות: אימייל, SMS, ‏push ותיבת הודעות
באפליקציה”. דברי בקול כל הזמן, גם לבד; אם יש חברה שמוכנה לשחק מראיינת, תני לה את סעיף 36.4 ובקשי ממנה לתת לפחות רמז
אחד. עבדי לפי השעון של סעיף 36.1.2, והשאירי שלוש דקות לסיום. את ההערכות אפשר לחשב בראש, או במחשבון של פרק 29.

**4. ציון.** מלאי את `mock-1-notifications.md` מיד, לפני הקריאה: ציון לכל קריטריון, והזמנים בפועל. ואז צלמי את
הלוח או שמרי את הדף ליד הקובץ.

**5. השוואה.** קראי את סעיף 36.4, ומלאי את העמודה „מה היה במקרה בפרק ולא אצלי”. כתבי שלושה תיקונים, כל אחד פעולה
לראיון הבא. למשל „לפני התרשים, לכתוב מספר אחד ולומר איזו החלטה הוא מכריע”.

**6. מעבר מהיר על שני מקרים.** בלי להסתכל בפרק: אמרי בקול את חמשת המשפטים על Hookline (סעיף 36.2.1), ועני על
שתי שאלות ההמשך של מגביל הקצב (סעיף 36.3.7). אחר כך בדקי מול הפרק.

## יום 97: ראיון שני, ומבחן עצמי על המאגר

**1. בחירת מקרה, בלי לקרוא אותו.** בחרי אחד מהשלושה שלא תרגלת: מתזמן עבודות (36.5), הזמנת כרטיסים (36.6), או
קליטת מדדים (36.7). קראי את שני האחרים, ואת הפתיחה של סעיף 36.8, עד תחילת המאגר עצמו.

<div dir="ltr" align="left">

```bash
cd ~/senior-course/ch36
cp templates/mock-scorecard.md mock-2-my-case.md
```

</div>

**2. הראיון והציון.** אותו תהליך כמו ביום 96: 45 דקות בקול, ציון מיד, ואז קריאה של המקרה והשוואה. כאן מספיקים שני
תיקונים.

**3. הכלי: התקנה ובדיקות.**

<div dir="ltr" align="left">

```bash
cd ~/senior-course/ch36/quiz

uv run ruff check . && uv run ruff format --check .
uv run mypy src
uv run quiz check ../data/questions.jsonl
```

</div>

הבדיקות מוצאות את המאגר בתיקייה `data/` שליד תיקיית הכלי, ולכן חשוב שהעתקת את שתיהן בצעד 1 של יום 96.

**4. הפקת המאגר לתוך הפרק.** הפקודה מחליפה את כל מה שבין שני הסימונים בסעיף 36.8 בטקסט שנוצר מהקובץ. היא רצה
בעותק של הספר:

<div dir="ltr" align="left">

```bash
cd $COURSE
uv run --no-project python tools/render_question_bank.py
git diff --stat
```

</div>

אם לא שינית את המאגר, הפרק לא משתנה, ו־`git diff` ריק. זו הבדיקה שהפרק והקובץ מסונכרנים.

**5. המבחן העצמי.** שני סבבים, אחד לכל חלק של המאגר. בכל שאלה, עני בקול לפני Enter, ואחרי התשובה סמני `y` רק אם
אמרת את הנימוק ואת הפשרה, לא רק את הכיוון:

<div dir="ltr" align="left">

```bash

uv run quiz ask ../data/questions.jsonl -n 10 -c go -c python -c backend -c distributed -c cloud-native
uv run quiz ask ../data/questions.jsonl -n 10 -c operations -c quality-security -c senior-craft -c coding -c project
```

</div>

‏`Ctrl-D` עוצר סבב באמצע, והסיכום נספר רק על השאלות שעברת. הדגל `--seed` עם מספר חוזר על אותו סבב, למשל אחרי
שבוע, כדי לראות אם השתפרת.

**6. רשימת נושאים חלשים.** צרי קובץ `weak.md`, ולכל שאלה שסימנת שלא ידעת: הפרק, החלופה, המחיר שלה, ומה הראיה
שלך. „ראיה” היא תרגיל שעשית או מספר שמדדת; אם אין, כתבי מה תעשי כדי שתהיה.

**7. שתי שאלות משלך.** הוסיפי לסוף המאגר שתי שורות על הנושאים הכי חלשים ברשימה, עם `id` של 136 ו־137, ובדקי:

## טעויות נפוצות ותיקונים

- **קראת את המקרה לפני הראיון.** הראיון הופך לשחזור, והציון לא אומר כלום. בחרי מקרה אחר מבין אלה שלא קראת, או
  תכנני את המקרה מסעיף ההעשרה של הפרק.
- **‏`FileNotFoundError: data/questions.jsonl not found` בבדיקות.** העתקת את תיקיית הכלי בלי `data/` לידה. הבדיקות
  מחפשות את המאגר בתיקיות שמעל קובץ הבדיקה; העתיקי את `data` לתוך `~/senior-course/ch36/`, כמו בצעד 1.
- **‏`quiz check` מדווח `chapter 34 outside coding (35-35)`.** הפרק של השאלה לא בטווח של הקטגוריה. בדקי בטבלת
  הקטגוריות למעלה, ותקני את אחד השדות; הבודק מדווח על כל השורות הבעייתיות יחד, עם מספר השורה.
- **‏`invalid JSON` אחרי שהוספת שאלה.** בדרך כלל מירכאות כפולות בתוך הטקסט. בתוך מחרוזת JSON כותבים אותן עם לוכסן
  הפוך לפניהן, או משתמשים במירכאות עבריות, „כך”, כמו בשאר המאגר.
- **העברית מופיעה הפוכה במסוף.** חלק מהמסופים לא מציגים טקסט מימין לשמאל. הכלי מדפיס את מספר השאלה, ואפשר לקרוא
  אותה בסעיף 36.8 של הפרק; או להריץ במסוף של VS Code, שמציג עברית טוב יותר.
- **תיקנת תשובה בפרק עצמו, והתיקון נעלם.** הטקסט בסעיף 36.8 נוצר מהקובץ, וכל הפקה דורסת אותו. מתקנים את
  `data/questions.jsonl`, ומפיקים מחדש.

## רמזים

- בראיון לבד, דברי בקול כאילו מישהי מקשיבה. מה שלא נאמר בקול לא נספר בציון, גם בראיון אמיתי.
- אם נתקעת בדקה העשרים בלי תרשים, זה הזמן לומר „אני מתחילה לצייר את מסלול הכתיבה”, ולהשאיר את השאר לצלילות.
- בהערכות, התחילי מהמספר של הפעולה החשובה ביום, וחלקי בכ־10 בחזקת 5. השיא הוא הנחה, וכותבים אותה עם סיבה.
- שאלה שסימנת `y` אבל רק „בערך” היא שאלה שלא ידעת. הרשימה החלשה שווה רק אם היא כנה.
- הקריאה של המאגר והבדיקה שלו נמצאות בפונקציה `load` בקובץ `bank.py`; כדאי לקרוא אותה לפני שמוסיפים שאלה.
